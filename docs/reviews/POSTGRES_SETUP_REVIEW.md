# PostgreSQL Directory Setup — Independent Review

Scope: the fixed non-secret directory helper and **unstarted** pinned PostgreSQL/pg_tde Compose candidate. This is not database, TDE, WAL, recovery or credential-runtime approval. Gate 2 remains NOT PASSED. The deferred input/output candidate is unchanged.

## Disposition

Independent adversarial review approves the narrow human directory-setup handoff. No blocking issue remains within that scope. The reviewer did not author the helper or deployment configuration. No privileged setup, key generation, container start or database migration was performed by the reviewer.

- The helper accepts no arguments, requires root, uses fixed paths and fd-relative directory opens with `O_NOFOLLOW`, checks ownership/mode/device and refuses nonempty leaves. It never recursively changes ownership or reads existing leaf files. Root-only mount and parent directories remain unchanged; only the seven empty service leaves receive the inspected image's UID/GID 26. Partial failure preserves existing state rather than deleting data.
- **PS-01, corrected:** the initial mapper check established a LUKS2 mapping name but not its intended backing image. Review requested strict UUID shape, exactly one loop slave, the fixed backing pathname and root-owned image/ancestor metadata. The revised helper includes these checks, preventing accidental use of different storage under the expected mapper name. This does not defend against a malicious root/kernel or concurrent privileged mount replacement; do not run concurrent project mount/setup operations.
- Root-only ancestors prevent the service from substituting leaf names during setup. A service that already owns an empty leaf can modify that leaf's contents, so this is an initial, service-stopped setup procedure, not a live repair tool. Unexpected/nonempty state refuses; no automatic retry or reset is authorized.
- Compose pins the image digest, UID/GID, non-root execution, no network, no capabilities, no new privileges, read-only root, core limit zero, equal memory and memory-plus-swap limits, CPU/PID ceilings and encrypted writable paths. Bind sources must already exist. The keyring is outside PGDATA; neither recovery-copy directory is mounted into PostgreSQL. No socket of another workload, root host mount or privileged container is present.
- Peer-only local administrator access and an empty listen address avoid a TCP/password bootstrap shortcut. The manual profile and restart-disabled setting prevent ordinary implicit startup. A profile is not an authorization boundary: explicit deployment must still validate the mount and runtime protections. Read-only config mounts do not make the source checkout immutable to its owner; the trusted administrator must avoid concurrent configuration edits.
